## 1. 背景与目标

### 1.1 背景

开发者的项目分散在磁盘不同目录中，项目信息（路径、版本、技术栈标签）依赖记忆或零散的 README；需求、设计、接口、计划等文档又散落在各个仓库里。结果是「项目在哪里、版本是多少、文档写了什么」需要反复查找。

Mana 用一个本地桌面客户端把这些信息收拢到一处：项目有据可查、项目组有清晰的归属、文档跟着项目/项目组走。数据只存本机 SQLite，不联网、不登录。

### 1.2 产品目标

1. **一处登记**：项目名称、标签、备注、路径、版本、所属项目组集中维护。
2. **两种归属**：项目可以独立存在，也可以归入项目组；项目组与项目都能管理文档。
3. **三步可达**：从首页或项目组页进入任意项目/文档，常用操作不超过 3 步。
4. **本地可靠**：所有写操作落 SQLite，异常不丢数据；启动即可用，无网络依赖。

### 1.3 成功指标（v1.0）

- 项目数 500、文档数 5,000 时，列表首屏渲染 < 100 ms，常用查询 < 50 ms。
- 新建项目、新建文档、切换项目组的完整操作均可在一个窗口内完成，无页面跳转等待。
- 冷启动到可交互 < 1.5 s（本机 SSD，不含首次系统字体加载）。
- 核心路径（项目 CRUD、组 CRUD、文档 CRUD）无阻断性缺陷。

## 2. 用户与场景

### 2.1 目标用户

| 角色 | 特征 | 核心诉求 |
|---|---|---|
| 独立开发者 | 同时维护 5–30 个仓库/实验项目 | 快速登记、快速找回项目路径和文档 |
| 小型研发团队负责人 | 按业务线/客户端/服务端分组 | 用项目组表达归属，沉淀组级规范与计划 |
| 技术写作者/维护者 | 文档与项目强关联 | 在项目内直接写 Markdown 文档并随时查阅 |

v1.0 为单用户本地工具，不做多账号、权限与协作。

### 2.2 典型场景

1. **登记新项目**：新建项目 → 填写名称、路径、版本、标签 → 归入「客户端应用」组。
2. **按组浏览**：左侧选中「后端服务」，右侧看到组内 4 个项目及其版本、更新时间。
3. **写项目文档**：打开项目详情 → 新建《接口设计》文档 → 编辑 Markdown → 保存。
4. **整理归档**：把项目从 A 组移动到 B 组；删除空组；删除项目前确认级联删除文档。
5. **找回上下文**：首页看到「最近更新」与「最近文档」，点开即回到项目/文档。

## 3. 范围

### 3.1 v1.0 范围内

- 项目的增删改查、搜索筛选、项目详情。
- 项目组的增删改查、组内项目添加/移出、组文档管理。
- 项目文档与组文档的增删改查（Markdown 内容）。
- 首页看板（统计、最近更新项目、最近文档、项目组概览）。
- 全局搜索（项目名、标签、路径、文档标题）。
- 本地 SQLite 持久化、数据初始化与迁移。
- 空状态、加载态、错误提示、删除二次确认、键盘快捷键。

### 3.2 不在 v1.0 范围

- 多用户、账号、权限、云同步、团队协作。
- Git 仓库解析、提交记录、CI/CD、看板/甘特图/工时。
- 文档附件上传、图片粘贴、在线预览 Office/PDF。
- 自动扫描磁盘发现项目、监听目录变化。
- 数据导入导出（放在 v1.1 候选）。
- 深色主题（跟随系统主题作为 v1.1 候选；v1.0 固定浅色）。

## 4. 术语与信息架构

### 4.1 术语

| 术语 | 定义 |
|---|---|
| 项目（Project） | 一个可独立开发、构建、维护的软件项目；必有名称，可无项目组。 |
| 项目组（Group） | 项目的集合，用于表达业务线、端侧或职责归属；组名全局唯一。 |
| 文档（Document） | 归属于某个项目或某个项目组的 Markdown 文本；归属者为且仅为一个。 |
| 未分组 | 虚拟分组，不落库；用于承载 `group_id` 为空的真实项目。 |
| 项目路径 | 项目源码在本机磁盘上的绝对路径，仅登记与跳转，不复制文件。 |

### 4.2 信息架构

```
Mana
├── 首页
│   ├── 概览统计
│   ├── 最近更新项目
│   ├── 项目组概览
│   └── 最近文档
└── 项目组管理
    ├── 左栏：全部项目 / 项目组列表 / 未分组
    └── 右栏：选中组的项目 / 文档
        └── 项目详情
            ├── 项目信息
            └── 项目文档（列表 / 编辑）
```

### 4.3 导航规则

- 主菜单固定两项：**首页**、**项目组管理**；当前项高亮，切换不丢滚动位置以外的状态。
- 项目详情是「项目组管理」内的二级页面，顶部提供面包屑与返回。
- 文档编辑是项目详情/组文档内的三级页面，保存或返回后回到来源列表。
- 「全部项目」是项目组管理左栏的虚拟入口，右栏展示所有项目（含未分组）。
- 项目组管理页首次进入选中第一个组；无组时展示引导空状态。

## 5. 功能需求

> 优先级：P0 = v1.0 必须；P1 = v1.0 应做（可在收尾阶段降级）；P2 = 后续版本。

### 5.1 FR-01 应用框架与导航（P0）

| 编号 | 需求 |
|---|---|
| FR-01-1 | 应用为单窗口桌面程序，默认 1440×900，最小 1120×720，窗口尺寸与位置可记忆。 |
| FR-01-2 | 左侧固定导航栏包含品牌区、首页、项目组管理；底部展示本地数据状态（SQLite 已连接）。 |
| FR-01-3 | 顶部栏包含当前页面标题/面包屑、全局搜索、通知、主操作「新建项目」；侧栏底部提供设置入口。 |
| FR-01-4 | 支持快捷键：`Ctrl/Cmd+N` 新建项目、`Ctrl/Cmd+Shift+N` 新建项目组、`Ctrl/Cmd+F` 聚焦搜索、`Esc` 关闭弹窗。 |
| FR-01-5 | 所有异步操作（保存、删除、加载）有进行中状态；失败时在操作附近给出可读错误，不使用仅控制台日志。 |

### 5.2 FR-02 项目管理（P0）

#### 5.2.1 项目字段

| 字段 | 必填 | 规则 |
|---|---|---|
| 名称 `name` | 是 | 1–80 字符；同一项目组内不重名（忽略大小写与首尾空格）；跨组允许重名。 |
| 标签 `tags` | 否 | 0–5 个；每个 1–16 字符；去重、去首尾空格；输入即校验。 |
| 备注 `description` | 否 | 0–1,000 字符；多行文本，用于目标、范围、注意事项。 |
| 项目路径 `path` | 否 | 绝对路径，0–512 字符；允许不存在（外部磁盘/未挂载），保存时提示但不阻断。 |
| 版本 `version` | 否 | 0–32 字符；建议语义化版本（如 `v1.4.0`），不强制格式。 |
| 所属项目组 `group_id` | 否 | 可为空（未分组）；只能引用已存在的组。 |
| 创建/更新时间 | 自动 | 系统写入；任何编辑刷新 `updated_at`。 |

#### 5.2.2 项目操作

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-02-1 | 新建项目：弹窗表单，字段同 5.2.1；保存后项目出现在所属组/未分组，并提示成功。 | P0 |
| FR-02-2 | 编辑项目：同一表单预填；保存后列表与详情同步刷新。 | P0 |
| FR-02-3 | 删除项目：二次确认，明确提示「该项目下的 N 篇文档将一并删除」，确认后级联删除。 | P0 |
| FR-02-4 | 项目列表：展示名称、标签（最多 2 个 + 余量）、版本、更新时间、路径摘要；支持按更新时间/名称排序。 | P0 |
| FR-02-5 | 项目详情：展示全部字段、所属组、创建/更新时间、文档统计；提供编辑、删除、打开目录、复制路径。 | P0 |
| FR-02-6 | 移动项目：编辑时更换项目组，或通过列表行菜单「移动到…」选择目标组/未分组。 | P1 |
| FR-02-7 | 打开目录：调用系统文件管理器定位到项目路径；路径不存在时提示并禁用该操作。 | P1 |
| FR-02-8 | 复制路径：一键写入剪贴板并 toast 提示。 | P1 |
| FR-02-9 | 项目搜索/筛选：关键词匹配名称、标签、路径；可按项目组、标签筛选；结果为 0 时给出空状态与清除筛选入口。 | P0 |

| 字段 | 必填 | 规则 |

| 标识色 `color` | 否 | 预设 6 色之一，用于左栏圆点与组标识；默认按创建顺序分配。 |

#### 5.3.2 项目组操作

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-03-1 | 新建项目组：弹窗填写名称、描述、标识色；创建后自动选中该组。 | P0 |
| FR-03-2 | 编辑项目组：修改名称、描述、标识色；名称冲突时就地报错。 | P0 |
| FR-03-3 | 删除项目组：二次确认；若组内有项目，明示「N 个项目将移至未分组，M 篇组文档将删除」，确认后执行。 | P0 |
| FR-03-4 | 组内添加项目：右栏主操作「新建项目」默认归属当前组；也可从其他组/未分组选择已有项目加入（P1）。 | P0/P1 |

| FR-03-6 | 项目组管理页为左右布局：左栏项目组列表（含全部项目、未分组、组名、项目数），右栏为选中组的项目列表与组文档。 | P0 |
| FR-03-7 | 左右两栏固定 280 px + 14 px 间距；拖拽调整列为后续版本。 | P1 |
| FR-03-8 | 左栏支持按组名搜索；组多时滚动，标题展示组总数。 | P0 |
| FR-03-9 | 右栏头部展示组名、描述、项目数/文档数，提供编辑、删除、新建项目操作。 | P0 |
| FR-03-10 | 右栏以「项目 / 文档」两个页签切换；默认「项目」，切到「文档」时保留当前组。 | P0 |

### 5.4 FR-04 文档管理（P0）

#### 5.4.1 文档字段

| 字段 | 必填 | 规则 |
|---|---|---|
| 标题 `title` | 是 | 1–120 字符；同一归属者下不重名。 |
| 类型 `kind` | 是 | 枚举：需求、设计、开发计划、接口、会议纪要、其他；默认「其他」。 |
| 正文 `content` | 否 | Markdown 文本，0–200,000 字符；自动保存草稿仅在编辑会话内，不落库直到保存。 |
| 关联链接 `link` | 否 | URL 或本机绝对路径，0–512 字符；仅作展示与跳转，不校验可达。 |
| 归属 `owner` | 是 | `(owner_type, owner_id)`：项目或项目组；创建后不可变更（v1.0）。 |
| 创建/更新时间 | 自动 | 系统写入；保存刷新。 |

#### 5.4.2 文档操作

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-04-1 | 新建文档：从项目详情或组文档页触发；填写标题、类型、正文、关联链接。 | P0 |
| FR-04-2 | 编辑文档：全屏编辑器，左侧 Markdown 源码、右侧实时预览；支持「编辑 / 预览」切换。 | P0 |
| FR-04-3 | 保存文档：校验标题与归属唯一性；成功 toast 并返回来源列表；未保存离开时二次确认。 | P0 |
| FR-04-4 | 删除文档：二次确认后硬删除；列表与统计同步更新。 | P0 |
| FR-04-5 | 文档列表：展示标题、类型、更新时间、字数；支持按更新时间/标题排序、按类型筛选。 | P0 |
| FR-04-6 | 文档预览：项目详情右侧可预览选中文档的前 200 字摘要；点击进入编辑器。 | P2 |
| FR-04-7 | 组文档：项目组管理右栏「文档」页签内管理，交互与项目文档一致。 | P0 |
| FR-04-8 | 文档搜索：全局搜索覆盖文档标题；组/项目内搜索覆盖文档标题与正文。 | P1 |

## 6. 业务规则

| 编号 | 规则 |
|---|---|
| BR-01 | 项目名称在同一项目组内唯一（未分组视为一个组）；比较时忽略大小写与首尾空格。 |
| BR-02 | 项目组名称全局唯一；项目组与项目可同名。 |
| BR-03 | 文档标题在同一归属者（项目或项目组）下唯一。 |
| BR-04 | 删除项目级联删除其全部文档；删除项目组时组内项目移至未分组，组文档级联删除。 |
| BR-05 | 移动项目不改变其文档归属；文档始终跟随原项目。 |
| BR-06 | 项目路径不存在只提示，不阻断保存；「打开目录」在路径不存在时禁用。 |
| BR-07 | 标签去重后保存；超过 5 个时阻止保存并提示。 |
| BR-08 | 所有删除操作必须二次确认；确认文案必须说明级联影响与数量。 |
| BR-09 | 所有时间以本机时区存储为 UTC 时间戳，界面按本地时区格式化；列表显示相对时间（如「2 小时前」），悬浮显示绝对时间。 |
| BR-10 | 并发写以单连接串行执行；跨表操作（删除组、移动项目）使用事务，失败整体回滚。 |
| BR-11 | 「未分组」不占用项目组 ID，不参与组排序与组删除。 |
| BR-12 | 项目组删除后不可恢复；v1.0 不提供回收站。 |

## 7. 页面与交互规格

### 7.1 首页

- 布局：左侧导航 228 px；主区顶部栏 56 px；内容区左右两栏（主列 2/3、侧列 1/3）。
- 统计卡：图标 + 数值 + 标签 + 环比说明；数值使用等宽数字（tabular-nums）。
- 最近项目表：6 行；表头吸顶；行悬浮浅灰；行尾 `更多` 菜单含编辑/移动/删除。
- 右侧项目组卡：每组一行（色点、组名、`N 项目 · M 文档`、右箭头）；底部「管理项目组」。
- 最近文档：4 条（2×2 网格），左侧类型图标，右侧相对时间。

### 7.2 项目组管理

- 左栏：标题「项目组」+ 计数；搜索框；「全部项目」入口；分组列表；「未分组」置底并用虚线分隔；底部「+ 新建项目组」。
- 右栏：组头部（标识色块、组名、描述、`N 个项目 · M 篇文档`）；右侧操作「编辑」「删除」「新建项目」。
- 页签：`项目 (N)` / `文档 (M)`；页签右侧为组内搜索与排序。

## 8. 数据模型

### 8.1 实体关系

```
project_groups 1 ──< projects 1 ──< documents
       │                              ▲
       └──────────────< documents ────┘   (owner_type='group')
```

- `projects.group_id` 可空；空值即「未分组」。
- `documents` 使用多态归属：`owner_type ∈ ('project','group')` + `owner_id`；由服务层保证引用有效。

### 8.2 表结构（SQLite）

> 连接启动时在迁移事务之外执行 `PRAGMA journal_mode = WAL;`（失败则降级为默认 journal）与 `PRAGMA foreign_keys = ON;`。迁移脚本本身只包含 DDL，不包含 PRAGMA。

```sql
CREATE TABLE project_groups (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT    NOT NULL COLLATE NOCASE,
  description TEXT    NOT NULL DEFAULT '',
  color       TEXT    NOT NULL DEFAULT '#7C5CFF',
  created_at  INTEGER NOT NULL,          -- Unix 秒（UTC）
  updated_at  INTEGER NOT NULL
);
CREATE UNIQUE INDEX ux_project_groups_name ON project_groups(name);

CREATE TABLE projects (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  group_id    INTEGER REFERENCES project_groups(id) ON DELETE SET NULL,
  name        TEXT    NOT NULL,
  tags        TEXT    NOT NULL DEFAULT '[]',   -- JSON 数组
  description TEXT    NOT NULL DEFAULT '',
  path        TEXT    NOT NULL DEFAULT '',
  version     TEXT    NOT NULL DEFAULT '',
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);
CREATE UNIQUE INDEX ux_projects_group_name
  ON projects(IFNULL(group_id, 0), name COLLATE NOCASE);
CREATE INDEX ix_projects_group ON projects(group_id);
CREATE INDEX ix_projects_updated ON projects(updated_at DESC);

CREATE TABLE documents (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  owner_type TEXT    NOT NULL CHECK (owner_type IN ('project','group')),
  owner_id   INTEGER NOT NULL,
  title      TEXT    NOT NULL,
  kind       TEXT    NOT NULL DEFAULT 'other',
  content    TEXT    NOT NULL DEFAULT '',
  link       TEXT    NOT NULL DEFAULT '',
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE UNIQUE INDEX ux_documents_owner_title
  ON documents(owner_type, owner_id, title COLLATE NOCASE);
CREATE INDEX ix_documents_owner ON documents(owner_type, owner_id, updated_at DESC);
```

> 说明：`projects.name` 的唯一索引使用 `IFNULL(group_id, 0)` 表达式，使未分组项目也受同一组内唯一约束；SQLite 支持表达式索引。

### 8.3 派生统计

- 首页/组头统计使用聚合查询实时计算，不落冗余字段：
  - 项目总数、组数、文档总数、近 7 天更新项目数。
  - 每组：`project_count`、`document_count`。
- 文档字数在保存时计算并可在列表查询中由 `length(content)` 派生（v1.0 不存冗余字段）。

### 8.4 迁移策略

- 使用 `schema_migrations(version INTEGER PRIMARY KEY, applied_at INTEGER)` 记录版本。
- 迁移脚本内嵌进二进制（`//go:embed migrations/*.sql`），启动时按版本顺序执行，单事务提交。
- v1.0 初始版本 `001_init.sql`；后续只增不改，保证已有数据库可升级。

## 10. 验收标准

### AC-01 项目 CRUD

- Given 空数据库，When 新建项目「Mana Desktop」并选择组「客户端应用」，Then 组内出现该项目，首页统计 +1，重启应用后仍存在。
- Given 同名项目已存在于同一组，When 再次创建同名项目，Then 表单提示「该组下已存在同名项目」，不写入数据库。
- Given 项目有 3 篇文档，When 删除该项目并确认，Then 项目与 3 篇文档均消失，统计同步减少。
- Given 项目路径为 `E:\codes\demo`，When 点击「打开目录」，Then 系统文件管理器打开该目录。

### AC-02 项目组 CRUD

- Given 组「客户端应用」有 5 个项目、5 篇组文档，When 删除该组并确认，Then 5 个项目 `group_id` 变为空并出现在未分组，5 篇组文档被删除，组消失。
- Given 已有组「后端服务」，When 新建同名组，Then 提示名称已存在，不创建。
- Given 左栏选中「客户端应用」，Then 右栏只展示该组项目与文档，计数与列表一致。

### AC-03 文档 CRUD

- Given 项目详情，When 新建《接口设计》并保存 Markdown，Then 文档出现在列表、字数正确、更新时间刷新。
- Given 文档标题在同一项目下重复，When 保存，Then 阻止保存并定位到标题字段。
- Given 编辑文档后未保存，When 点击返回，Then 弹出「放弃未保存的修改？」确认。
- Given 组文档页签，When 新建文档，Then 文档归属该组，不影响任何项目文档。

### AC-04 首页与搜索

- Given 16 个项目、5 个组、42 篇文档，Then 首页四项统计与数据库一致，最近项目按更新时间倒序。
- Given 搜索「atlas」，Then 下拉结果包含名称/标签/路径命中的项目，Enter 打开详情。
- Given 搜索不存在的词，Then 展示空结果提示，不出现空白下拉框。

### AC-05 稳定性

- Given 数据库中项目数 500、文档数 5,000，When 打开项目组管理，Then 列表在 100 ms 内完成首屏渲染，滚动无明显卡顿。
- Given 保存过程中关闭窗口，Then 已提交事务不丢失，未提交事务回滚，下次启动数据一致。
